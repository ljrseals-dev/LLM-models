# Realm-Quant integration

This package is integrated from the merged Python workbench in ljrseals-dev/realm-quant (PR #3). The upstream implementation is retained in src/realm_quant and licensed under its accompanying MIT license.

## Actual quantization modes

- FP16: converts floating-point weights to FLOAT16 while preserving model I/O tensor types. Requires onnxconverter-common.
- Dynamic INT8: uses ONNX Runtime dynamic weight quantization, per-channel, for selected operators (default MatMul and Gemm). Operators outside the selected list remain unchanged.
- Ternary: writes a packed 2-bit symbol sidecar with per-output-channel scales, plus an ONNX model whose weights are reconstructed to floating point for normal ONNX Runtime execution. This does not provide native ternary arithmetic or a speedup claim.

## Registry command

Install the optional quantization stack:

```sh
python3 -m pip install -r tools/quantization/requirements.txt
```

Then:

```sh
bash cli/llm-models quantize publisher/model --mode fp16
bash cli/llm-models quantize publisher/model --mode int8 --op-types MatMul,Gemm
bash cli/llm-models quantize publisher/model --mode ternary --threshold-ratio 0.7
```

Use --artifact ARTIFACT_ID when the manifest contains multiple ONNX artifacts, and --output DIR to choose a new output directory. The CLI verifies the input SHA-256 immediately before quantization and refuses external ONNX tensor-data references and existing output directories.

Each output contains model.onnx, provenance.json, and derived-manifest.fragment.json. Ternary mode also creates model.ternary.npz and model.ternary.json. The fragment describes output artifacts and parentage so they can be added to a separately versioned model manifest after review. The command does not mutate the registered source manifest.

## Validation

The integration tests exercise 2-bit packing, ternary invariants, actual ONNX model rewriting, ONNX Runtime execution, and numerical comparison. They use synthetic models and do not claim validation of any third-party production checkpoint.

```sh
python3 tools/quantization/test_quantization.py
python3 tools/quantization/test_onnx_integration.py
bash tools/quantization/test_cli_quantize.sh
```

The integrated Python package also retains the upstream inspection, numerical comparison, and neural-audio WAV encode/decode/roundtrip commands. They can be invoked with PYTHONPATH=src python3 -m realm_quant.cli; WAV commands use soundfile. These research workbench commands are not aliases for registry deployment and are not exposed as StackAlign operations.

The Python quantizer and Cmajor ONNX emitter are separate paths. Dynamic INT8 models may contain ONNX Runtime quantized operators that the Cmajor code generator does not support. Ternary sidecars are not consumed by the current Cmajor emitter; its separate packed-ternary metadata contract is not automatically generated by Realm-Quant. FP16 output can be passed to the Cmajor preparation path, which promotes supported FLOAT16 initializers to FLOAT32 constants.
